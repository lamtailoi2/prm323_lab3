# Taste
- Writes to the agent in Vietnamese and expects replies in Vietnamese (code, commands, and file paths stay as-is). Confidence: 0.7
- For evidence screenshots, wants one full-screen capture per UI state, taken directly on the emulator he is currently running against the real app/signed-in test account — not rendered from a temporary fake-data harness, and not redacted (no white blocks painted over names/emails/phones). Confidence: 0.8
- For video evidence, wants one recording per test case — start recording, run exactly that case, stop, then start a fresh recording for the next case (separate files named per TC) rather than one long continuous take; recording is part of running the case, so the two happen together ("vừa chạy vừa quay lại từng TC"). Confidence: 0.7
- The video he actually hands in is one consolidated file per test case, not one file per run/trace: merge that case's counted runs and name it `TC-XX_<Descriptive_Name>` (e.g. `TC-19_Change_CV.mp4`, `TC-14_Sign_out.mp4`), leaving smoke/extra runs out. Confidence: 0.55
- Wants command sequences he can paste and run to a visible result in his own Windows/PowerShell setup — a bare step that finishes with nothing on screen (e.g. `adb install` with no launch/verify follow-up, or a tool assumed to be on PATH) gets called out ("Success không có gì cả"); make each step self-contained and end with how to confirm it worked. Confidence: 0.55
- When a procedure gets complicated, wants it rewritten from the start as one linear numbered path with a single choice per step (no branches, alternatives, or corrective sub-cases woven in) — scattered options read as "rối quá". Confidence: 0.6
- When handed a list of remaining fixes, wants them executed sequentially — one item at a time, each verified and reported before starting the next ("làm lần lượt giúp tôi"), not bundled into one big pass. Confidence: 0.55
- Prefers the agent to actually carry a task through to a real, verified result itself (build, deploy functions, install APK, drive the emulator, report actual on-device output) instead of only handing him steps to do it — when offered "I can build/install and guide you step by step", he answers "chạy giúp tôi", and in UI flows he expects the agent to resolve the missing data itself (look up the real company email and fill it in) and to perform the final action (press the Send button) rather than stopping at a placeholder or leaving the last click to him. Confidence: 0.7
- Wants feature behaviour grounded in the actual data it names: e.g. CV↔job matching must derive the technologies named in the CV and compare them against the job description, with the scoring kept deterministic rather than letting the model decide the result. Confidence: 0.5
- Keeps an eye on change-set size and pushes back on sprawling diffs ("sao changes bị nhiều file quá vậy") — prefers tightly scoped changes and minimal edits to existing files over whole-file rewrites that touch many unrelated files. Confidence: 0.55
- When asking for test cases to be (re)written, expects the agent to first inspect the real code/run the real flow to learn how it actually behaves, then write the cases against that observed behaviour ("trước đó kiểm tra trước xem các luồng hoạt động như thế nào", "kiểm tra thật kỹ giúp tôi luồng hiện tại trong code") — not to draft cases from assumptions; also expects that order for runs — study the code flow first, then drive the E2E agent ("tìm hiểu luồng trong code hiện tại như thế nào trước, rồi sau đó mới chạy artemis"). Confidence: 0.75
- Expects an end-to-end case to cover the whole journey to its final state, not stop at an intermediate hand-off (e.g. open the mail draft → send → return to the app → press "I've sent it"); a test that ends mid-flow reads as failing/incomplete to him. Confidence: 0.5
- Calls out pointless repetition inside a flow: if a step already succeeded or is another case's job (e.g. the `To` field already correct, and TC-18 owns the Gmail recipient step), don't keep clearing and re-typing it — "rồi cứ xóa mail rồi điền lại làm gì vậy". Each case should do only what that case is testing, without retry loops. Confidence: 0.55
- Wants technical explanations of a codebase's tools/tech ordered as: concept (khái niệm) → how it works (nguyên lý hoạt động) → where/how it is implemented in the actual code (file paths and function names), not a bare feature list. Confidence: 0.5
- When a tool fails because a dependency is missing on his machine, wants the dependency installed and the intended path made to work — not a substitute workaround silently accepted (he asked to set up scrcpy/ffmpeg so ARTEMIS's own session recording works, instead of the earlier `adb shell screenrecord` fallback: "thiếu scrcpy chạy luôn phần này"). Confidence: 0.6
- Rejects the agent inventing requirements on its own: don't apply a rule found in a repo doc (e.g. evidence/README.md's "Never include personal data") as if he had asked for it, and don't add extra steps like redaction; ask first or do only what was requested. Confidence: 0.75
